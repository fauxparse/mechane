UI component defaults audit

Repeated Tailwind overrides reveal a shared editor-inspector language. Make production-supported defaults explicit where the product contract is editor-first; use named presets where a primitive must remain context-neutral.

Audited 2026-08-25 · Production consumers under apps/; stories are visual coverage only

At a glance

Decision Make repeated editor-specific Tailwind bundles into defaults when the product contract is editor-first, or into named presets when the primitives must remain context-neutral. Stories are descriptive examples, not evidence against changing a default.
3/3SelectTrigger uses share the inspector field bundle

The most consistent overrides are compact inspector controls. The report below separates exact duplicate bundles, production-supported default candidates, and frequent but mixed overrides.

Scope and method

  • Scanned consumer TSX under apps/; production callsite counts exclude design-system implementations and examples.
  • Recorded Storybook/component stories separately as visual coverage. Stories are descriptive examples, not evidence against changing a default.
  • Measured repeated className utility tokens and exact class bundles, then checked each component's current implementation default.
  • Treated repeated production usage as evidence for a default only when the surrounding semantics and layout were also consistent.

Recommended changes

1. SelectTrigger compact default or inspector preset

Highest confidence

Evidence: CanvasInspectorSections.tsx:185, TextSection.tsx:331, and StrokeSection.tsx:92.

All three production uses pass size="sm" and repeat the same field treatment: 

w-full rounded-sm border-0 bg-muted/50 px-2

Make this compact treatment the default if the design system is editor-first, or add an inspector preset if the component must serve broader surfaces. The treatment is compact size, full width, rounded-small shape, borderless muted surface, and one dark-mode rule. Migrate all three callsites and remove the duplicated classes and size prop.

Stories remain visual examples and should be updated to make whichever generic/default and inspector states are intentionally supported explicit.

2. SidebarContent flush default or vibe

High confidence

Evidence: CanvasLayers.tsx:502, CanvasInspector.tsx:26, and SingleNode.tsx:20.

Every production use overrides the component's default p-2 with p-0. Change the default to p-0 if the design system is editor-first; otherwise add a flush or inspector vibe option and migrate those three callsites.

The current story's padded examples do not count against this change; they should be updated or made explicit according to the desired default contract.

3. Textarea taller default or editor variant

High confidence

Evidence: TextSection.tsx:401 and SourceValueDialog.tsx:58.

Both production textareas repeat:

min-h-40 resize-y

Change the default to min-h-40 resize-y if all product textareas are editor-like; otherwise add an editor or multiline variant, then remove the repeated className.

Stories are coverage examples, not a reason to retain the compact min-h-16 default.

4. Make Toggle small by default or add inspector vibe

Production-wide

Evidence: all 8 application Toggle callsites pass size="sm".

If the design system is editor-first, change the default Toggle size to sm and remove the redundant props. If the primitive is intended to serve broader contexts, add the inspector vibe instead. Story examples document supported visual states; they do not veto the production-supported default.

5. Add a semantic graph-action button variant

Exact duplicate

Evidence: BaseNode.tsx:89-95 and FlowNode.tsx:71-82.

Both buttons use variant="ghost", size="icon", and this exact visual bundle: 

text-(--flow-muted-foreground) hover:text-(--flow-muted-foreground)
bg-transparent hover:bg-transparent opacity-50 hover:opacity-100

Add a quiet or graphAction variant for these colors, surface, and opacity rules. Keep size explicit because the neighboring BaseNode action uses icon-sm.

6. Add a compact destructive alert variant

Exact duplicate

Evidence: Header.tsx:364-367 and Header.tsx:369-372.

The two publish-menu alerts repeat:

mb-1 rounded-sm border-0 bg-destructive/25 p-2
text-destructive-foreground ring-1 ring-destructive

Add an Alert variant such as menu-destructive. Keep mb-1 local because it is menu layout spacing. The existing alert already has semantic variants in alert.tsx:6-19.

7. Add a pill variant to TabsTrigger

Exact duplicate

Evidence: Header.tsx:244-258.

Both editor tabs repeat:

rounded-[100vw] border-0 px-3

Add a pill or compactPill trigger variant. Keep the surrounding TabsList surface local to the Header; it is a navigation treatment, not a universal tabs default.

Shared inspector variant contract

Recommended API Use one cross-component vibe="inspector" contract, optionally supplied by an InspectorProvider around each Canvas and graph inspector. Use vibe, not variant, so Button's semantic variants remain independent.

Common contract

Inspector vibe means compact control height (h-7 where applicable), rounded-sm, compact horizontal padding, muted inspector surface, borderless field chrome, and centralized dark-mode styling. Focus, disabled, invalid, and keyboard behavior remain unchanged.

Section, SectionRow, SectionHelperText, SidebarContent, and SidebarHeader are already inspector shell components. Dialog, Tabs, DropdownMenu, Tooltip, ImageInput, and CopyButton participate in inspector flows but are overlays/actions, not inline field-vibe controls.

Provider shape

<InspectorProvider>
  <CanvasInspector />
</InspectorProvider>
<InspectorProvider>

Components resolve vibe from the nearest provider; a local vibe prop opts one control out. This makes both inspector surfaces converge without repeating the prop at every callsite.

Implementation order

  1. Add one InspectorProvider/vibe context and mount it at both Canvas and graph inspector roots.
  2. Implement the shared vibe="inspector" contract for Input, InputGroup and children, SelectTrigger, Toggle, ToggleGroup, ToggleGroupItem, Button, Textarea, and custom PropertyInput/TypeSelect controls.
  3. Remove proven redundant overrides: compact SelectTrigger classes, SidebarContent p-0, Textarea min-h-40 resize-y, eight Toggle size="sm" props, and three InputGroupButton size="icon-xs" props.
  4. Decide whether editor-first defaults should become component defaults or remain provider-scoped; stories do not answer this question.
  5. Add semantic variants for graph actions, split-button bodies, compact destructive alerts, and Header tab pills.
  6. Update stories as descriptive visual coverage for the selected contract, then run component-specific typecheck and smoke verification.

Risks and migration notes

Visual verification matters Verify Tailwind merge order, focus rings, dark-mode surfaces, mixed-value inspector states, scrollbars, and nested sidebar groups after migration.
  • Compose vibe styles before consumer className so explicit callsite overrides remain possible.
  • p-0 changes the content box, not only whitespace; check keyboard focus and scrolling.
  • Provider propagation must not cross modal/overlay boundaries accidentally; preserve each component's semantic variants.
  • Do not delete local classes until every cited callsite uses the selected default or provider vibe and visual coverage documents the resulting states.

Conclusion

Recommended direction Use one shared vibe="inspector" context across Canvas and graph inspector controls. It centralizes compact height, radius, padding, muted surface, border treatment, and child propagation while preserving each component's semantic variants. Make those defaults global only if the design system is intentionally editor-first; otherwise keep them provider-scoped.
