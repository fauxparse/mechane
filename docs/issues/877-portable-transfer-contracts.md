# Clipboard implementation handoff and file import/export contracts

Design for [#877](https://github.com/fauxparse/mechane/issues/877), under [#866](https://github.com/fauxparse/mechane/issues/866). This document defines required interfaces, not implemented functionality. No production clipboard, adoption, live-write or file feature is delivered here. The driving developer chose shared portable contracts and mechanics, with file UX and whole-Show backup left to separate efforts.

## Decision and alternatives

Share the versioned lossless graph-fragment and typed Source-value contracts, plus their transport-independent codecs and application logic. Keep plain Source JSON a separate data representation. A future file adapter may carry these envelopes directly or wrap them in a separately versioned container. It must not create another definition comparator, reference remapper or graph application implementation.

Separate clipboard/file representations translated into a common model were considered. They would allow unrelated file conventions, but would add another lossless encoding to maintain before file requirements exist. One universal Show/value/backup representation was rejected. Expanded Source data deliberately loses authored inheritance and graph context, while a backup needs a scope and restoration policy this fragment contract does not supply. Sharing mechanics does not require identical formats, limits or UX for a future backup.

Use existing packages for the implementation. Pure projection, comparison, compatibility and reconciliation belong in `packages/domain`; strict portable codecs and composite authored operations belong in `packages/commands`; authenticated capture, resource staging, application and outcomes belong in `apps/api`; gesture routing and pending interaction state belong in `apps/studio`. Do not build a generic transport framework or hypothetical file adapter now.

## Portable codec and format ownership

`PortableCodec.decode(handoff, expectedKind)` returns `ValidatedGraphFragment` or `ValidatedValue`, or a diagnostic. `encode(validatedContent, mode)` returns complete JSON text plus byte/record counts. Both are pure, bounded and transport-independent. `handoff` is an immutable list of representations exposed by one chosen read, each with media type and text. The codec never reads a clipboard, file, URL, Show or asset catalog.

`expectedKind` is graph or value and comes from the captured explicit target. Exact recognized identifiers reserve envelope meaning. Reject wrong kind, unknown fields, unsupported versions or malformed recognized envelopes without plain-data fallback. Compare recognized representations exposed by that same handoff after strict decoding, ignoring JSON object-key order but preserving ordered arrays, authored absence/inheritance and local sharing. A disagreement rejects the handoff. Never read again to discover concealed custom data.

The portable codec owns envelope versions and the closed version-1 projection schema. It must not serialize `ShowGraph`, a GraphQL response, DB rows or `GraphEdit[]` wholesale. Domain types supply the authored vocabulary; explicit allowlisted portable projections exclude nonportable fields. Every domain variant added later requires an explicit codec decision. Adding a wire field is a new version, not permission for old readers to ignore it. Version 1 accepts version 1 only. No historical migration is included.

### Version-1 member layout

All listed envelope members are required. Empty collections use `[]`; nullable context uses `null`. Record variants admit only their specified members. Domain configuration members retain their existing optional-versus-explicit-absence meaning, and graph capture must not normalize sparse inheritance away.

| Envelope       | Members                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Graph          | `format: "mechane/show-graph"`, `version: 1`, `origin`, `content`, `transfer`.                                                                                                                                      |
| Graph origin   | `showId`, `draftVersion`. Informational source scope/revision, never permission or a destination selector.                                                                                                          |
| Graph content  | `roots`, `nodes`, `edges`, `sourceDefaults`, `canvases`, `shapes`, `blocks`, `interactions`, `boundary`, `assets`.                                                                                                  |
| Graph transfer | `null` for copy/export/duplicate, or `{cutIntentId}` for a Cut handoff. The opaque hint is untrusted and has no deletion authority without server verification. It is excluded from authored definition comparison. |
| Typed value    | `format: "mechane/source-value"`, `version: 1`, `origin`, `type`, `root`, `shapes`, `records`.                                                                                                                      |
| Value origin   | `showId`, `plane: "default" \| "current"`. No executable Source, Run, Instance or write instruction.                                                                                                                |
| Plain value    | The expanded JSON value itself, with no envelope or declared source Type.                                                                                                                                           |

Graph collections have these responsibilities:

- `roots` lists selected top-level identities after removing redundant selections already covered by a selected Flow. `nodes` includes their contained children exactly once. Node projections retain authored names, positions, colors, parent membership, Flow size/default, Variables, ports, Types, Transformer configuration and Device `perConnection`. They exclude `editorMetadata`, `pairingCode` and `liveDomain`.
- `edges` contains internal Wiring/Device-driver records with their authored paths, mappings, conversions and routes. Navigate/Update projections are absent; their owning Actions in `interactions` retain route layout and regenerate projections after remapping.
- `sourceDefaults` retains sparse authored entries with Source identity, stable Field path and value. Omitted override and explicit Typed Absence must remain distinct. The new authored replacement operation must encode explicit absence without using the old reset/clear instruction.
- `canvases` records Scene owner, Canvas identity, authored Artboard facts and flat Elements with `parentId` and `rank`. Block records own the same Canvas projection. Element projections include complete authored properties, Slots, input assignments and fallbacks. Root/topology validation follows ADR 0014 with no added authored nesting cap.
- `shapes` and `blocks` contain full reachable authored definition snapshots, including Shape defaults, Block Variables, States/overrides and nested references. `interactions` contains `cues`, `actions`, `eventBindings`, `slotEventBindings` for copied Scene and Block owners, each once. Block Cues remain actionless.
- `boundary` describes original parent context and references crossing the selected node set. Each edge reference identifies its copied endpoint, original external endpoint and complete port/path/configuration. Action references identify the copied owning Action and original target. Context never imports unselected content or permits rewriting its consumers.
- `assets` contains unique `{assetId, revision}` pairs derived from every image use in content and definitions. Validate manifest equality with those uses, not only that listed assets exist. No delivery URLs, credentials, digests offered as authority, or image bytes.

Typed value Type grammar is the existing primitive string, `{kind: "array", of: Type}` or `{kind: "shape", shapeId}`. Shape metadata contains `id`, `name`, and ordered `fields`; each Field has `id`, `name`, `type`, `required`. Unlike graph Shapes, there is no `defaultValue`. Shape/Field IDs are original Show-scoped metadata, never destination bindings.

Typed `root` and record values are JSON scalars, `null`, `{assetId, revision}`, or `{ref: token}`. Record tokens are payload-local strings, not encoded live IDs. Shape records have `id`, `kind: "shape"`, `type`, `fields`; array records have `id`, `kind: "array"`, `type`, `items`. `fields` uses source Field IDs interpreted through the supplied metadata; plain JSON uses exact human names. Every reachable Shape/array gets one record. Repeated references preserve sharing; all references must resolve. Record order carries no value semantics; item and Field order do. Copy emits optional absence explicitly as `null`. Destination compatibility maps exact Field names, including declared Types/requiredness for absent values and empty arrays. Paste allocates one fresh identity per local token.

### Bounded strict parsing and record accounting

Check UTF-8 bytes before parsing, including all envelope/context text. Each supplied representation must fit 10 MiB inclusive. Use duplicate-key-aware JSON parsing before constructing ordinary objects; ordinary `JSON.parse` alone is insufficient. Reject non-finite numbers and unsafe prototype handling. Use iterative bounded traversal for deep data rather than a new depth cap. Do not execute Formula text.

`countLogicalRecords` is one exhaustive visitor shared by producer, consumer and authoritative validation. Total limit is 100,000 inclusive:

| Count once per logical entity                                                          | Counting rule                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Graph node, connection, Canvas, Element, Variable/input port                           | Identity in its defined owner scope. Include boundary connection entities once, not again for their context description. A projected Navigate/Update edge is not a second entity beside its Action.                                             |
| Shape, Shape Field, Block, Block Variable, State                                       | Identity in its owner scope, shared definitions once. Block Canvas/Elements use the same Canvas/Element rule.                                                                                                                                   |
| Cue, Cue Parameter, Action, Event Binding, Slot Event Binding                          | Identity in its owner scope.                                                                                                                                                                                                                    |
| Source-default entry, State Override, Slot Input Assignment, binding Parameter mapping | Each authored entry at its owner/path, even without an independent ID. These are content records, not their encoding wrappers.                                                                                                                  |
| Structured Shape/array value or template                                               | Typed records once per local identity. Graph templates once per authored template identity. Plain JSON objects/arrays once per occurrence; repeated expanded trees count separately. An image pair is a simple typed value, not a Shape record. |

Do not count envelope objects, collection tables, roots/origin/boundary context descriptors, asset-manifest pairs, Type descriptors, references, paths, property descriptors, layout/style objects, scalar values or mapping dictionaries as additional records. Their bytes still count. Traverse structured data according to its declared value/template location, not every JSON object in Element configuration. Validate all supplied entities, including unused malformed records, before accepting; never use reachability pruning to evade validation or limits. Outbound closure omits unused records under the fixed capture rules.

## Shared module interfaces

Names below are implementation contracts, not claims that these symbols already exist. Semantic IDs, versions, cut/session handles, snapshot keys and operation IDs must be distinct types. Validated content and commit-ready plans are opaque results, not caller-constructed casts.

### Coherent capture and preparation

| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AcceptedEdits.persistThrough(cutoff)`             | Accepted graph/Canvas command watermark → acknowledged draft version or save failure.                                     | Flush/wait only through fixed cutoff. No `saving === false` inference, debounce delay or recovery-policy change. Cancellation detaches capture waiting, not accepted saves.                              |
| `GraphCapture.capture(request, actor)`             | Show, selected roots, expected draft version → frozen fragment and capture revision.                                      | Owner-authorized, one repeatable-read transaction through executor-aware readers. Exact version equality; complete owned/definition closure including unopened Canvases. No publication or Run mutation. |

### Definition comparison and structural remapping

`DefinitionComparison.compare(capturedDefinitions, originalDestinationDefinitions)` returns an unchanged-original eligibility map with changed/missing dependencies. Normalize object-key order only; preserve authored identities, names/order, defaults/inheritance, complete owned content, nested definitions and exact asset revisions. Compare full reachable closure. A changed dependency disqualifies its ancestor, not necessarily unchanged descendants. Foreign Shows have no automatic definition reuse candidate. Do not substitute another same-named or structurally similar definition.

`GraphReconciliation.prepare(fragment, destinationSnapshot, placement, choices, resourceFacts)` returns a pending preview: fixed destination/base version, fresh/reused identity maps, containment, automatic names, required repairs, optional omissions, asset occurrence groups and a final-application eligibility result. It is pure given authenticated resource facts. It does not query a browser, mutate resources or accept clipboard names as authoritative metadata.

`ReferenceRemapping.apply(fragment, identityMap, externalBindings, assetRevisionMap)` returns fully reconciled content or rejects. Allocate copied-owned IDs once, including Scene/Canvas/Element/Variable/port/Cue/Parameter/Action/binding/template IDs and fresh imported definition/Field/State IDs. Reused definitions retain original IDs. Every copied reference to a shared definition uses one mapping. Only verified same-Show movement bypasses fresh owned-ID allocation.

Remap recursive Shape Types; Field paths and `fieldMapping` keys/values; Source Defaults/templates; Slots/Block Variables/inputs; Property Connections and fallbacks; State Override Element IDs; Cue ownership/order; Event/Slot bindings/Parameter mappings; graph endpoints and containment. Preserve internal Field/Variable/port/Cue/State names and Formula text. Reproject Navigate/Update edges from authored Actions. An exhaustive visitor must fail when a new reference-bearing domain variant lacks handling.

Placement is explicit input from the interaction adapter, not inferred from payload provenance. #875 owns pointer/centre coordinates, 8px repeat-anchor detection, 24-unit cascade, mixed Flow/Device fragments, selection and camera. Duplicate passes original containment and its chosen offset. Reconciliation applies #870's scope rules and never modifies an unselected consumer, driver, Action or existing Flow default to make a fragment fit.

### Candidate eligibility, repairs and frozen refresh

`GraphCandidates.read(pendingTarget, actor)` returns authorized destination snapshots/candidates grouped by Flow/Show scope, with eligibility/reasons and exact versions. Only authorized incompatible candidates may appear disabled. Unauthorized metadata must not leak. Candidate display is not commit authorization.

Use explicit choice variants, not optional-field bags:

- Navigate repair identifies copied owning Scene/Cue/Action and an eligible destination Scene in the chosen Flow.
- Update repair identifies owning Action, destination Source and complete source/destination Field-path mapping with declared operand/Parameter Types. Changing Source invalidates dependent path choices. Mapping never coerces or fills defaults.
- Optional Wiring/Device-driver choice identifies only the copied consumer/Device plus explicit compatible producer/port/path or Leave disconnected. Same-Show automatic original bindings require exact identity and eligibility.
- Image replacement identifies one original `{assetId, revision}` dependency and one authorized active destination `{assetId, revision}`. It replaces all copied uses of that dependency, including reachable Block/State uses, never another revision grouped by name.

`AssetOccurrences.index(fragment)` returns exact dependency groups with use count and inspectable owner/content paths. `ReconciliationSummary` lists created/reused definitions, chosen available names, verified reused/newly adopted destination revisions and optional disconnections. Reused image revision/name/alt metadata remain unchanged. Automatic results need disclosure, not mandatory approval.

`GraphReconciliation.refresh(frozenFragment, sameTarget, retainedChoices, currentFacts)` creates a new preview/base version. Keep still-valid choices, clear invalid choices, expose changed automatic maps and required repairs. Never reread the clipboard, recapture the source or refresh-and-submit. A new matching asset cannot silently replace a staged mapping. #880 owns dialog/focus/dismissal and final-action presentation.

### Authenticated asset staging and adoption

`AssetAdoption.stage(fragmentKey, destination, exactDependencies, replacements, actor)` returns an opaque stage handle and authoritative `AssetRevisionMap`. It binds the frozen fragment, destination/base version, source/replacement/reuse exact revisions and verified immutable blob identities. A stage is not a visible catalog entry or successful standalone adoption.

Each map entry identifies original asset/revision, destination asset/revision, and `reused` or `created`. Reuse requires an active destination-owned catalog entry with server-verified matching blob content, retaining its revision/name/alt metadata. Fresh adoption creates a destination-owned entry using catalog revision conventions and source metadata. Do not copy physical bytes, follow URLs, trust a supplied digest, revive deleted rows or use the same-Show `sourceAssetId` relationship as cross-Show authority.

`AssetAdoption.commit(stage, transaction, actor)` is internal to graph application. Recheck source read and destination write authorization, all exact active source/replacement/reuse revisions, usable backing content and destination version. Commit catalog creation plus backing retention references plus reconciled graph/definitions in the same atomic boundary. Invalidated access/resource/mapping rejects all of it. No independently visible adoption transaction followed by a best-effort graph write.

`AssetAdoption.discard(stage)` affects only this uncommitted stage. It cannot delete reused resources, shared immutable blobs or independently committed catalog assets. Committed destination entries retain backing content independently of source asset/Show deletion. Undo retains adopted catalog entries. Ordinary later destination deletion may still make its images unavailable. Blob storage deletion must respect all destination retention references; staging must hold usable content until commit or safely reject if it is lost. This guarantee needs new lifetime logic, not an assumption about today's upload implementation.

Standalone value validation accepts only authorized, active destination-owned exact image revisions. It cannot call graph adoption to repair a foreign value. A future file carrying bytes needs a separate upload/container design; possession of bytes or a fragment never waives application authorization.

### Value preparation and replacement

`ValueCompatibility.prepare(validatedValue, explicitTargetContract)` returns exact-name recursive Type/Field mapping and fresh-clone plan or rejection. Typed checks use the declared contract even for absence/empty arrays. Plain checks use actual values against the destination Type. No extra Fields, missing required Fields, defaults, coercion, Shape import, fuzzy matching, merging or append.

Model targets as distinct variants:

- Default: Show, draft base version, Source and optional stable Field path.
- Current Show-level: Show, exact active Run, published graph version, Source and optional Field path.
- Current Shared Instance: the same Current facts plus explicitly chosen configured Shared Device/eligible existing Instance and Flow relationship.

`ValueReplacement.prepare(target, clonePlan, actor)` returns a pinned comparison/confirmation snapshot, actual holder scope and disclosed alias effects. Current confirmation covers selected value/record closure and target reference bindings. Root replacement rebinds only the selected Source; Field replacement writes its existing containing holder and propagates through aliases. Reject inaccessible ancestors, incoming wiring, cross-scope holders, remote per-connection targets and stale graph/publication/Run eligibility as #872 specifies.

`ValueReplacement.commit(operationId, preparedRequest, actor)` repeats authorization/eligibility and atomically compares the selected value/closure and bindings before writing clones plus holder. Field comparison ignores unrelated sibling value changes; a global Run sequence is not the comparison. No fresh target selection, fallback, force overwrite or implicit retry. Default is one authored command/history entry, preserving explicit absence and untouched sibling inheritance; Current has no editor history. Default edits and Default Undo/Redo must cease the existing Default-to-Current synchronization.

### Authored application and authoritative outcomes

`GraphApplication.commit(operationId, pendingPlan, stageHandle, transferReservation, actor)` performs one atomic version-checked authored operation. The optional reservation is a typed copy-versus-verified-move variant, not a payload flag. Recompute/recheck domain invariants, explicit repairs, candidate authorization, exact maps, asset stage and affected-object preconditions under the transaction. Preserve representable unpublishable drafts; saved and published are separate result facts.

On success return committed version, authoritative amendments/provisioning facts, inserted/moved root IDs and history/resource receipt. Fresh copied Devices receive fresh server provisioning; same-Show moves preserve existing identity/pairing/domain without delete/recreate. No arbitrary submitted edit batch may bypass these checks.

`OperationOutcomes.lookup(operationId, actor)` returns `pending`, `committed(receipt)` or `rejected(diagnostic)`, with access checks. The client adds `unknown` when transport cannot establish one of those outcomes. Persist operation identity/request binding and the committed receipt in the same transaction as mutation. Repeated submission of the same identity cannot reapply or bind to another request. A missing/unobservable result is not proof of rejection; lookup must reconcile with the commit path before returning a definitive rejection.

Keep outcomes addressable for unresolved operations and their dependent transfer steps; ordinary expiration must not turn unknown into safe-to-retry. This operation record is not durable Undo. History remains session-local. Unknown pins the submitted target, blocks Paste/Duplicate/history and holds a Cut reservation. Check result reads that exact operation; it never reapplies. Definitive rejection allows a fresh explicit preparation/confirmation with a new operation ID. Copy/Cut remain available under the resolved interaction policy.

## Verified Cut authority and transfer progression

Cut needs an authenticated server module. LocalStorage/BroadcastChannel may notify tabs, but cannot establish authority or originating-session liveness.

| Interface                                                                                    | Required behavior                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OriginSessions.open(authSession, editorInstance, show)` / `renew(handle)` / `close(handle)` | Bind origin to authenticated owner/editor/Show. Use server-checked liveness with fail-closed expiry for lost tabs, plus explicit revocation on navigation/reload/closure. A heartbeat is liveness evidence, never source freshness. An old handle cannot reopen after revocation. |
| `CutIntents.prepare(captureKey, deletionSet, originHandle, actor)`                           | Create inactive single-use intent bound to coherent captured revision, frozen-content fingerprint, exact owned deletion set and origin. Include reusable dependencies in content, never in deletion ownership. Return an opaque transferable hint.                                |
| `CutIntents.activate(intent, successfulWriteReceipt, actor)`                                 | Activate only after the origin adapter reports the corresponding successful browser handoff and while origin/revision/capture remain valid. Late write completion cannot reactivate revoked authority. Failure removes nothing.                                                   |
| `CutIntents.inspect(hint, fragmentKey, actor)` / `revoke(handle, reason)`                    | Verify actor, fingerprint, exact source revision/set and live origin. New Cut, source revision change, cancellation or origin invalidation revokes unsubmitted authority. Invalid/missing/reserved/consumed authority requires explicit Paste as copy, never silent movement.     |
| `Transfers.reserve(intent, destination, operationId, actor)`                                 | One atomic reservation across tabs, tied to destination attempt. Preflight both Shows, removal blockers, optional losses and Device/domain consequences. Same-Show movement uses verified current objects, not older snapshot replacement.                                        |
| `Transfers.settle(reservation, destinationOutcome)`                                          | Destination commit consumes intent atomically. Definitive failure releases only if intent remains valid. Unknown retains reservation; a timeout cannot release it.                                                                                                                |
| `Transfers.removeSource(transferId, removalOperationId, actor)`                              | Cross-Show only, after confirmed destination success and while origin/transfer is still eligible. Recheck complete deletion set, source version/access and surviving required Action/Flow-default blockers. One pinned removal operation; no duplicate submission.                |

Liveness expiry is a conservative refusal, not permission for delayed deletion or a promise to detect OS tab closure instantly. Production must specify its renewal interval/expiry and exercise process loss before release; these timings do not change the single-use/active-origin contract. An already submitted operation may commit after navigation. Revocation stops new/dependent submission, not authoritative lookup or a promised rollback.

Same-Show move commits position/containment/legal reference changes and intent consumption together as one operation/entry. Cross-Show transfer commits fresh destination import first, then separately submits source removal. Cancellation between them, source rejection or lost origin leaves both and reports pasted; originals not removed. Destination and source entries are independent. No cross-Show transaction, compensating Undo, automatic cleanup, clipboard restoration or renewed Cut on Undo.

## Created-versus-reused resource history

`HistoryReceipt` records operation-owned node/Canvas/interaction/template identities; prior selected authored state including sparse inheritance/sharing; source-removal owned content/connections; and separate created/reused definition and image mappings with exact revisions and expected content facts. It is the input to existing session-local forward-command history, not a new server Undo interface.

Undo removes operation-owned graph content only when affected-object/reference checks pass. Never delete reused definitions/assets. Compute removable newly imported definition closure together: edited definitions and surviving consumers retain those definitions and required dependencies; internal references among definitions removed together are not surviving consumers. Retention is intentional. If graph removal itself breaks surviving references, reject the whole history operation.

Keep newly adopted image catalog entries on Undo. Redo restores the operation's owned identities, not a new Duplicate; verify retained definitions, identity availability, exact active assets and authorization. Missing/conflicting resources reject the whole edit without reminting, substitution or renewed source adoption. Device history restores authored configuration and retained server pairing identity but cannot reclaim domain bindings, connections or observed live effects. Current replacement never enters this history.

## Diagnostics

Use a discriminated result with category, stage, stable reason code, safe affected owner/path and next action. Categories are browser failure, rejected input, repair required, ready with warnings, commit rejected, client outcome unknown and committed. Stages distinguish persistence, capture, encode, browser read/write, decode, compatibility, reconciliation, asset staging, application, source removal and history.

Reasons include unsupported kind/version, conflicting representations, malformed/duplicate key, limit, incompatible Type, unaddressable target, stale version/value, unavailable-or-not-authorized resource, unresolved required Action, invalid move authority and publication blocked. Do not reveal inaccessible private resource metadata. Supplied labels render as text. Clipboard refusal is not a Run Error and needs no persistent diagnostic ledger. Actionable recovery follows the fixed policy: explicit native Paste, finish gesture/save recovery, re-copy, repair/cancel, refresh frozen preview, fresh live read/confirmation or exact result lookup. No automatic consent loop or retry.

## Browser and future file adapters

The browser adapter owns focus/gesture routing, immutable same-handoff collection, feature detection, HTTPS/focus/permission failures, serialized submitted writes and #875/#876 presentation. Cold graph Copy/Cut prevents default without `setData`, prepares, then requires another explicit gesture. It never writes on readiness/focus return. Native Paste uses event `clipboardData` only. Optional custom formats supplement mandatory portable `text/plain`. Async-read denial offers explicit native Paste without a second automatic read. Ready text is written without another fetch. Submitted writes cannot be cancelled/restored as rollback.

#890 exercised Chrome for Testing 154 on local macOS with substantial headless/native-CDP and explicit-permission probing, plus an initial headed smoke. Its accepted gaps remain: retail/current-previous browser matrix, other browser families/OSes, cross-family transfer, physical shortcuts/menus, normal permission prompts and wholly unsupported custom-format behavior. Transported fixture metadata is not proof of strict codecs, fresh cloning, capture, adoption, authorization or Show application. This handoff adds no browser certification claim and does not repeat that probe as production work.

A future graph-fragment file reader supplies file bytes to the same strict codec, then the same explicit target, reconciliation, repair and authenticated application interfaces. A value file reader supplies plain JSON or the typed value envelope to the same explicit Default/Current target contract, including live confirmation and no live Undo. File selection and origin metadata never authorize mutation. File export has no Cut/session intent by default; remove `transfer` authority hints when encoding an ordinary export. A file cannot become a move merely because it contains a copied hint.

Separate efforts must decide extensions/media types, container version/compression, asset byte inclusion/upload and offline portability, file chooser/save/cancellation UX, multi-file application, streaming/archive security, limits for different products, historical migration and compatibility policy. Backup additionally needs content scope including unused resources/settings, identity restore versus new-Show clone, ownership/secrets exclusions, destination creation/overwrite, Run inclusion/exclusion, Device/domain restoration, consistency/retention and restore failure semantics. Do not freeze those decisions by calling version-1 fragments backups.

## Acceptance examples for the implementation

These are required consumer-visible checks, not claims of executed production behavior. Exercise public module interfaces with real domain fixtures and transaction/authorization races. Do not test only forwarding, source text or fixture echoes.
